LangChain.js Agent Harness 速查

配套课程：Lesson 13 — Agent Harness 与 Middleware

一句话模型

Agent = Model + Harness。模型负责生成下一步，harness 负责把合适的 prompt、tools、state、context 和 Middleware 组织到每次调用周围。 
invoke(input, context)
  │
  ├─ beforeAgent       一次：初始化或校验
  ├─ beforeModel       每次模型调用前：更新 state
  ├─ wrapModelCall     包住模型调用：改请求、重试、路由、记录
  ├─ model             返回 AIMessage 或 tool_calls
  ├─ afterModel        每次模型调用后：观察或更新 state
  ├─ tools             执行工具，再回到 beforeModel
  └─ afterAgent        一次：收尾

State 与 Context

维度 State Context
生命周期 可跨调用持久化 只属于本次 invoke
典型内容 messages、计数、工作流字段 用户 ID、租户、角色、请求元数据
Middleware 读取 state runtime.context

最小模板

import { createAgent, createMiddleware } from "langchain";
import { z } from "zod";

const contextSchema = z.object({ userId: z.string() });

const audit = createMiddleware({
  name: "AuditMiddleware",
  contextSchema,
  stateSchema: z.object({ modelCalls: z.number().default(0) }),
  beforeModel: (state, runtime) => {
    console.log(runtime.context.userId);
    return { modelCalls: state.modelCalls + 1 };
  },
  wrapModelCall: (request, handler) => handler(request),
});

const agent = createAgent({
  model,
  tools,
  middleware: [audit],
  contextSchema,
});

await agent.invoke(
  { messages: [{ role: "user", content: "..." }] },
  { context: { userId: "user-001" } },
);

选型速记

  • 只需要模型自主调用工具：从 createAgent 开始。
  • 需要给循环增加横切能力：优先 Middleware。
  • 需要显式节点、分支、并行、长流程：把 Agent 放进 LangGraph 工作流。
  • 需要规划、文件系统、子 Agent 等成套能力：评估 Deep Agents。
