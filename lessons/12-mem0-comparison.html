实验场景

一个个人助手，需要记住用户偏好并跨对话个性化回复。三句话：

  1. "我喜欢简洁的回复风格" — 偏好声明
  2. "我下周要去东京出差" — 计划声明
  3. "帮我总结一下我的偏好和计划" — 记忆召回测试

方案 A: Store API（80 行代码）


Graph 有 4 个节点:

START → load()        → respond()    → extract()     → END
         │                │              │
     getStore()       LLM 使用        LLM 提取事实
     .get(profile)    memoryContext    store.put()
                                      更新 profile

你需要自己写:
- 提取 prompt: "从消息中提取新事实，JSON 数组..."
- 搜索逻辑: 手动构造函数匹配
- 去重逻辑: 手动对比已知事实

方案 B: Mem0 模式（30 行代码）


Graph 只有 1 个节点:

START → chat() → END
          │
     mem0.search()   → 内置语义搜索
     LLM + 记忆上下文  → 生成回复
     mem0.add()      → 内置事实提取+去重

你不用写:
- 提取 prompt — Mem0 内置
- 搜索逻辑 — Mem0 内置语义 + BM25 + 实体
- 去重逻辑 — Mem0 自动合并

核心对比表

维度 Store API Mem0
代码量 ~80 行（4 节点） ~30 行（1 节点）
提取 prompt 自己写 内置
检索方式 key 精确匹配 语义 + BM25 + 实体
去重 手动 自动 + 实体链接
控制粒度 完全控制 信任黑盒
时序推理 需自己实现 2026.4 起内置
成本 免费 Free(10K) → $19/月 → $249/月

选择指南

Store API 适合：原型、学习项目、小型应用、需要完全控制记忆逻辑的场景。你已经在 Lesson 11 中掌握了。

Mem0 适合：生产级应用、需要语义搜索的场景、多用户系统、不想自己维护提取/去重/搜索逻辑的场景。

两者可以组合

// 实际生产中的最佳实践：两者互补

const ProdState = Annotation.Root({
  messages: Annotation(/* 消息累积 */),
  step: Annotation(/* 工作流状态 → Store API */),
  decision: Annotation(/* 审批决定 → Store API */),
});

// Store API 管应用状态（结构化、精确、需要控制）
await store.put(["workflow", tid], "state", { step, decision });

// Mem0 管用户记忆（非结构化、语义化、需要智能）
await mem0.add(messages, { userId });
const memories = await mem0.search(query, { filters: { userId } });

知识检查

1. Store API 和 Mem0 最核心的区别是什么？
A. Store API 是开源的，Mem0 是商业产品
B. Store API 是基础工具（put/get/search），Mem0 是产品化方案（内置提取/去重/语义搜索）
C. Store API 只能存文本，Mem0 可以存图片
D. Store API 是 Python 的，Mem0 是 TypeScript 的
2. 生产环境中，Store API 和 Mem0 的正确使用方式是？
A. 必须二选一，不能同时使用
B. 互补使用 — Store API 管应用状态，Mem0 管用户记忆
C. 用 Mem0 完全替代 Store API 和 checkpointer
D. 用 Store API 封装 Mem0，让 Mem0 只做持久化
