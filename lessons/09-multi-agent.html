Lesson 09: 多 Agent 协作 — Pipeline · Router · Supervisor

📅 2026-07-17 ⏱ ~25 分钟 🎯 用 LangGraph 编排多个专职 Agent 协同工作 📎 课前要求: Lesson 08 LangGraph Agent

你将要学会的

  1. Pipeline 模式 — Agent 按固定顺序接力，前一个的输出是后一个的输入
  2. Router 模式 — 一个路由节点判断意图，分发到不同的专职 Agent
  3. Supervisor 模式 — 主管 Agent 动态分派任务给工人，收集结果后汇总
  4. 三种模式的选择标准 — 什么时候用哪种

问题：单个 Agent 的局限

前八课我们构建的都是单 Agent 系统——一个模型 + 一组工具。这在大多数场景下够用，但当任务变复杂时：

  • 一个 Agent 的 system prompt 既要研究又要写作，容易顾此失彼
  • 不同任务需要不同的工具集，单 Agent 的工具列表太臃肿
  • 无法并行处理多个子任务
多 Agent 协作就是解药。把一个大任务拆成多个小任务，每个 Agent 专注一件事。LangGraph 的图结构天然适合编排多 Agent——每个 Agent 是一个节点（或子图），它们之间通过 State 传递数据。

cd learn-langchain
npx tsx 09-multi-agent.ts

三个演示依次运行，展示三种不同的多 Agent 协作模式。

模式 1: Pipeline — 串联接力

START → 研究员 Agent (搜索+整理) → 撰稿人 Agent (写作) → END

每个 Agent 有不同的 system prompt 和工具集：

  • 研究员: 只有 search_docs 工具。System prompt 说「只收集资料，不做分析」
  • 撰稿人: 没有任何工具。System prompt 说「根据研究笔记写结构报告」

研究员的结果通过 researchNotes State 字段传给撰稿人：

const PipelineState = Annotation.Root({
  messages: Annotation({ reducer: (l, r) => l.concat(r) }),
  researchNotes: Annotation({ reducer: (_, r) => r }), // ← 研究员写入，撰稿人读取
});
特点 Pipeline
结构 固定顺序，A→B→C
适合 任务有明确的上下游依赖
示例 搜索→筛选→写作｜编码→审查→测试

模式 2: Router — 一次分发

          ┌→ 数学 Agent (calculator 工具)
START → 路由节点 ─┼→ 搜索 Agent (search_docs 工具)
          └→ 通用 Agent (无工具)

路由节点分析用户意图，分发到对应的专职 Agent。每个 Agent 只知道自己的领域：

// 路由函数 — 根据用户意图选择 Agent
function routeToAgent(state) {
  return state.nextAgent; // "math" | "search" | "general"
}

const routerGraph = new StateGraph(RouterState)
  .addNode("router", routerNode)      // 判断意图
  .addNode("math", mathAgentNode)     // 只有 calculator
  .addNode("search", searchAgentNode) // 只有 search_docs
  .addNode("general", generalAgentNode) // 没有工具
  .addConditionalEdges("router", routeToAgent, {
    math: "math", search: "search", general: "general",
  })
  // 所有 Agent 执行完 → END
  .addEdge("math", END).addEdge("search", END).addEdge("general", END)
Router vs Pipeline 的区别：Pipeline 是 A→B→C 所有节点都走一遍。Router 是根据条件走一条路（互斥分支），一个请求只经过一个 Agent。

模式 3: Supervisor — 动态分派 + 循环汇总

START → 主管 Agent → 工人 Agent → 主管 Agent → 工人 Agent → ... → 主管: END
         │              │              │
         分析任务          执行工具           汇总报告

这是最灵活的协作模式。主管 Agent 负责：

  1. 分析: 用户需要什么？拆成哪些子任务？
  2. 分派: 调用哪些工人？传什么参数？
  3. 汇总: 工人执行完了，结果够不够？不够继续分派，够了就汇总输出

工人 Agent 只负责执行——调用工具，返回事实性结果。

// 主管和工人形成循环
const supervisorGraph = new StateGraph(SupervisorState)
  .addNode("supervisor", supervisorNode)
  .addNode("worker", workerNode)
  .addEdge(START, "supervisor")
  .addConditionalEdges("supervisor", routeAfterSupervisor)
  .addConditionalEdges("worker", routeAfterWorker)
  // supervisor → worker → supervisor → worker → ... → END

三种模式对比

Pipeline Router Supervisor
结构 固定顺序 一次分发 动态分派+循环
Agent 数 2-3 3-N 3-N
适合场景 有明确前后依赖 任务类型互斥 复杂任务需多轮
控制权 图结构 路由规则 主管 Agent
灵活性 低 中 高
选择指南：固定依赖 → Pipeline，互斥类型 → Router，动态多轮 → Supervisor。三者也非互斥——一个复杂的 Supervisor 的子工人本身可以是一个 Pipeline。

知识检查

1. Pipeline 模式和 Router 模式最大的区别是什么？
A. Pipeline 需要更多 GPU 内存，Router 不需要
B. Pipeline 所有 Agent 都依次执行（串联），Router 只执行被路由到的那个（互斥分支）
C. Router 只能用于数学计算，Pipeline 只能用于文本生成
D. Pipeline Agent 不能调用 LLM，Router Agent 可以
2. Supervisor 模式中，主管 Agent 不做什么？
A. 分析用户任务，拆分为子任务
B. 亲自调用所有工具执行子任务
C. 收集工人执行结果，汇总为最终回答
D. 动态决定继续分派工人还是停止
3. LangGraph 在多 Agent 协作中的核心价值是什么？
A. 自动为每个 Agent 生成最优的 system prompt
B. 用图结构（节点+边+State）显式定义 Agent 之间的协作关系和数据流动
C. 让多个 Agent 在一个 GPU 上并行推理
D. 提供 Agent 之间的加密通信通道
