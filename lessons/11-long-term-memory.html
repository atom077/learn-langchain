Lesson 11: 长期记忆 — Store API 与跨线程持久化

📅 2026-07-23 ⏱ ~25 分钟 🎯 用 LangGraph Store 构建跨会话、跨线程的持久化记忆系统 📎 课前要求: Lesson 05 Memory + Lesson 10 Human-in-the-loop

你将要学会的

  1. Store API — put/get/search，二级命名空间键值存储
  2. Memory 生命周期 — Load(加载记忆) → Use(Agent使用) → Extract(提取新事实) → Save(持久化)
  3. 跨线程记忆共享 — 不同对话线程共享同一个 Store 中的长期记忆

回顾：Lesson 05 的 Memory 是短期的

Lesson 05 教的 Buffer/Window/Summary Memory 都是消息级别的短期记忆——它存在于 State.messages 数组中，依赖 checkpointer 持久化，生命周期绑定到一个 thread_id。

  • 换个对话 → 记忆丢失
  • 服务重启（没有持久化 checkpointer）→ 记忆丢失
  • 想记住"用户喜欢简洁风格"——只能靠 Summary，不精确
Store API 是真正的长期记忆。它独立于对话线程——一个 Store 可以被所有线程共享。用户档案、偏好、提取的事实，都是 Store 的典型用途。

cd learn-langchain

核心 API

API 参数 说明
store.put(namespace, key, value) ["users","001"], "profile", {...} 写入或更新数据
store.get(namespace, key) ["users","001"], "profile" 精确读取一条数据
store.search(namespace, opts) ["users"], {limit: 10} 按命名空间前缀搜索
store.delete(namespace, key) ["users","001"], "profile" 删除一条数据
getStore() — 在节点内部获取 Store 实例

命名空间设计

// Store 用 namespace + key 两级来组织数据
store.put(["users", "user-001"], "profile", {...})
//      ─────── namespace ──────  ── key ──

// 推荐的分层结构:
["users",    "<id>"]              → 用户档案
["users",    "<id>", "facts"]     → 从对话中提取的事实
["users",    "<id>", "prefs"]     → 用户偏好
["org",      "products"]          → 组织/产品信息
["sessions", "<id>", "summary"]   → 会话摘要
search 的巧妙之处：store.search(["users"]) 返回所有用户的数据——因为 namespace 前缀匹配。这让你可以"列出所有用户"而不需要单独维护一个索引。

演示 2: Memory 生命周期

每个请求经过四个阶段，形成一个闭环：

      ┌──────────────────────────────────────┐
      │            Memory 生命周期             │
      │                                      │
      │  1. LOAD                             │
      │  ┌──────────────────────┐            │
      │  │ getStore().get()     │            │
      │  │ 读取用户档案+事实     │            │
      │  └──────┬───────────────┘            │
      │         │ 注入 system prompt          │
      │         ▼                            │
      │  2. USE                              │
      │  ┌──────────────────────┐            │
      │  │ Agent 使用记忆上下文   │            │
      │  │ 个性化回复            │            │
      │  └──────┬───────────────┘            │
      │         │                            │
      │         ▼                            │
      │  3. EXTRACT                          │
      │  ┌──────────────────────┐            │
      │  │ LLM 从对话中提取新事实  │            │
      │  │ "我今天学了 Rust" → 事实 │           │
      │  └──────┬───────────────┘            │
      │         │                            │
      │         ▼                            │
      │  4. SAVE                             │
      │  ┌──────────────────────┐            │
      │  │ store.put() 持久化    │            │
      │  │ 新事实追加到 facts[]   │            │
      │  └──────────────────────┘            │
      └──────────────────────────────────────┘

运行结果验证了闭环：4 轮对话后，用户的已知事实从 3 条增长到 5 条——"学了 Rust"和"下周做 Q3 Review PPT"都被 LLM 自动提取并持久化。

短期记忆 vs 长期记忆

短期记忆 (Messages) 长期记忆 (Store)
存储 State.messages 数组 Store put/get/search
生命周期 单线程内 跨线程、跨会话
数据类型 LLM 消息 任意 JSON
典型用途 当前对话上下文 档案、偏好、事实
类比 工作记忆 长期记忆
