Lesson 07: LangGraph — 构建有状态 Agent 工作流

📅 2026-07-15 ⏱ ~25 分钟 🎯 用 LangGraph 构建显式控制的 Agent 工作流 📎 课前要求: Lesson 06 实战项目

你将要学会的

  1. LangGraph 是什么 — 跟 createAgent() 的本质区别
  2. StateGraph — 定义状态、节点、边，编译为可执行图
  3. Annotation 自定义 State — 不只是 messages，还能追踪业务数据
  4. 条件分支 — 路由函数决定执行路径，实现 "if 意图=A → 走这条路"

问题：createAgent 不够用的时候

你在前六课用的 createAgent() 是自主决策——Agent 自己决定调用哪个工具、推理到什么时候停止。这很灵活，但有两个痛点：

  1. 不可控 — 你无法保证 Agent 一定走某条路径。「先验证用户身份 → 再执行操作」这种顺序，Agent 可能跳过
  2. 无状态 — 除了消息历史，你没法在流程中追踪「当前在第几步」「已经处理了多少条」
LangGraph 解决的就是这两个问题。它让你显式定义工作流——每个步骤是一个节点（Node），步骤之间的跳转是边（Edge），流程中携带的数据是状态（State）。

核心概念

概念 类比 说明
State（状态） 流水线上的产品 在节点之间流动的数据。每个节点读取 state、返回部分更新
Node（节点） 工位 一个函数，接收 state、返回更新。可以调用 LLM、执行代码、调用 API
Edge（边） 传送带 定义节点间的跳转规则。固定边（A→B）或条件边（A→B 或 C）
Reducer 合并策略 定义 state 字段如何合并新值和旧值。追加（messages）、覆盖（count）、累积（notes）

演示 1: 线性图 — 两个节点串联

最简单的 LangGraph：两个节点，一条直线。

import { StateGraph, MessagesAnnotation, START, END } from "@langchain/langgraph";

const graph = new StateGraph(MessagesAnnotation)
  .addNode("think", (state) => {
    // state.messages 是所有累积的消息
    return { messages: [{ role: "assistant", content: "正在思考..." }] };
  })
  .addNode("reply", (state) => {
    return { messages: [{ role: "assistant", content: "你好！" }] };
  })
  .addEdge(START, "think")   // 入口 → think
  .addEdge("think", "reply") // think → reply
  .addEdge("reply", END)     // reply → 出口
  .compile();

await graph.invoke({ messages: [{ role: "user", content: "你好" }] });

StateGraph(MessagesAnnotation) 创建图，MessagesAnnotation 是最简单的 State——只包含一个 messages 数组（自动累积）。

演示 2: 自定义 State — 用 Annotation 追踪业务数据

真实场景不只追踪 messages，还需要业务状态——比如第几轮对话、操作日志。

const CounterState = Annotation.Root({
  messages: Annotation({              // 消息：追加累积
    reducer: (left, right) => left.concat(right),
    default: () => [],
  }),
  count: Annotation({                 // 计数：新值覆盖旧值
    reducer: (_, right) => right,
    default: () => 0,
  }),
  notes: Annotation({                 // 日志：数组累积
    reducer: (left, right) => [...left, ...right],
    default: () => [],
  }),
});
Reducer 是关键。它定义了「当节点返回新值时，如何跟旧值合并」。left 是旧值，right 是新值。messages 用 concat（追加），count 用 right（覆盖），notes 用 spread（累积）。

演示 3: 条件分支 — 路由函数

这不只是一个「if/else」——它是把业务逻辑注入图结构的方式。

const branchGraph = new StateGraph(MessagesAnnotation)
  .addNode("classify", classifyNode)    // 分类节点
  .addNode("calculate", calcHandler)    // 计算分支
  .addNode("time", timeHandler)         // 时间分支
  .addNode("chat", chatHandler)         // 聊天分支
  .addEdge(START, "classify")
  .addConditionalEdges("classify", (state) => {
    // 路由函数：读取 state，返回下一个节点名
    const msg = state.messages.at(-1);
    if (msg.content.includes("算")) return "calculate";
    if (msg.content.includes("时间")) return "time";
    return "chat";
  })
  .addEdge("calculate", END)
  .addEdge("time", END)
  .addEdge("chat", END)
  .compile();

LangGraph vs createAgent：什么时候用哪个？

维度 createAgent (ReAct) LangGraph
控制方式 Agent 自主决策 你显式定义图
确定性 低（LLM 可能走偏） 高（代码决定路径）
适合 开放域对话、灵活任务 审批流、Pipeline、多步处理
状态 隐式（只有消息） 显式（自定义字段 + reducer）
分支/并行 不支持 原生支持
经验法则：用户说「帮我做 X」→ createAgent（自主探索）。你规定「先 A → 根据结果走 B 或 C → D」→ LangGraph（显式控制）。

知识检查

1. Annotation.Root 中每个字段的 reducer 函数的作用是什么？
A. 定义字段的 TypeScript 类型，用于编译时检查
B. 定义节点返回的新值如何与旧值合并——追加、覆盖还是累积
C. 定义该字段在哪个节点中被写入，防止并发冲突
D. 定义该字段的默认值在什么时候被重置
2. LangGraph 跟 createAgent() 最大的区别是什么？
A. LangGraph 只能处理文本，createAgent 可以调用工具
B. createAgent 用 Agent 自主决策，LangGraph 由你显式定义节点和边来控制执行流程
C. LangGraph 运行速度比 createAgent 快 10 倍
D. createAgent 不支持 TypeScript，LangGraph 支持
3. 下面哪种场景更适合用 LangGraph 而不是 createAgent？
A. 开放域聊天，用户问什么答什么
B. 先验证用户权限 → 执行操作 → 记录审计日志 → 发送通知，这个固定流程
C. 让 Agent 自己决定调用哪些工具来回答用户问题
