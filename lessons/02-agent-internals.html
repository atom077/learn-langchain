核心概念：ReAct 决策循环

第一课你看到了 Agent 自动选择了工具并给出答案。但中间发生了什么？答案是 ReAct（Reasoning + Acting）——Agent 在一个循环中交替进行"思考"和"行动"。

┌─────────────────────────────────────────────────────┐
│                  ReAct Agent Loop                    │
│                                                      │
│  ┌──────────┐    ┌──────────┐    ┌──────────┐       │
│  │  THINK   │───▶│   ACT    │───▶│ OBSERVE  │       │
│  │ (model)  │    │ (tools)  │    │ (result) │       │
│  └──────────┘    └──────────┘    └──────────┘       │
│       ▲                              │               │
│       │        还需要更多信息?        │               │
│       └──────────────────────────────┘               │
│                      │                               │
│              任务完成? ▼                              │
│              ┌──────────┐                            │
│              │  ANSWER  │  ← 最终回复                │
│              └──────────┘                            │
└─────────────────────────────────────────────────────┘
  1. Think（模型请求） — LLM 分析当前状态，决定回答还是调用工具
  2. Act（工具执行） — 框架执行 LLM 请求的工具调用
  3. Observe（观察结果） — 工具结果被追加到消息历史，LLM 下一轮看到它们
  4. Answer 或继续循环 — 如果信息够了直接回复，否则回到步骤 1
关键洞察：Agent 的每一步推理都是纯文本消息的追加——Think 追加一条 ai 消息，Act 追加一条 tool 消息，下一轮 Think 看到完整的对话历史再做决策。这个简单机制解释了 Agent 所有的"智能"行为。

四种消息类型

类型 发送者 作用
system 开发者 设定 Agent 的行为边界、角色、规则
human 用户 用户的问题或指令
ai LLM 模型的输出：文本回复 或 工具调用请求
tool 框架 工具执行后的返回值，被注入回对话历史

消息如何推动循环 — 真实例子

[0] system  | 你是一个总是先算一遍再确认的助手。用中文回复。
[1] human   | 1 + 1 等于几？
[2] ai      | 我先算一下。1 + 1 = 2 让我用计算器确认一下。 [tool_calls: calculator]
[3] tool    | {"expression":"1 + 1","result":2}
[4] ai      | 确认计算结果为 2。所以，1 + 1 等于 2。✅

stream() vs invoke()

invoke() stream()
返回值 最终结果（完整的消息数组） AsyncIterable，每个 chunk 是循环中的一个步骤
chunk 结构 N/A { model_request: {...} } 或 { tools: {...} }
适用场景 API 调用、批处理、只需要最终答案 聊天 UI、调试、需要实时反馈的交互

System Prompt：控制 Agent 的行为

const result = await agent.invoke({
  messages: [
    { role: "system", content: "你是一个严谨的数学助手。每次计算都必须用 calculator 工具验证。" },
    { role: "user", content: "1 + 1 等于几？" },
  ],
});

System prompt 最佳实践：角色设定、工具使用规则、输出格式、语言 & 长度限制。

Agent 的错误恢复能力

在 02-stream-demo.ts 的输出中，你会看到 Agent 调用 calculator 时出错了（LLM 编造了一个不存在的 round 函数），但它自动检测错误并重新调用——这就是 ReAct 闭环控制的价值。

知识检查

1. 在 ReAct 循环中，model_request chunk 后紧跟的是什么类型的 chunk？
A. 另一个 model_request，形成递归推理
B. tools chunk（如果 Agent 请求了工具调用），否则循环结束
C. 一个 HTTP 请求发送到 LangSmith 进行追踪
D. 一个 system chunk 用来更新 Agent 的行为规则
2. 什么类型的消息用来设定 Agent 的行为规则，并且在对话中不会被工具调用打断？
A. human 消息——用户的要求就是最高规则
B. tool 消息——工具的返回值定义了可用操作
C. system 消息——在对话开始时注入，持续影响 LLM 的行为
D. ai 消息——Agent 自己给自己设定规则
3. 下列哪个场景最适合用 stream() 而不是 invoke()？
A. 一个夜间批处理任务，需要处理 10000 条数据
B. 一个需要向用户实时展示 Agent 推理步骤的聊天界面
C. 一个微服务 API，只需要返回最终的计算结果
D. 一个单元测试，验证 Agent 的最终输出是否正确
