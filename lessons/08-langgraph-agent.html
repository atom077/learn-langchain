Lesson 08: LangGraph Agent — LLM 节点 + 工具节点

📅 2026-07-16 ⏱ ~25 分钟 🎯 在 LangGraph 中手动构建 ReAct 循环，注入自定义步骤 📎 课前要求: Lesson 07 LangGraph 入门

你将要学会的

  1. 手动 ReAct 循环 — 不用 createAgent()，在 LangGraph 中自己构建 LLM → tools → LLM 循环
  2. LLM 节点 — model.bindTools() 让模型在图中能请求工具调用
  3. 工具节点 — 执行 LLM 请求的工具调用，返回 tool message
  4. 注入自定义步骤 — 在 LLM 和工具之间插入审核、日志、验证

问题：createAgent 是个黑盒

createAgent() 封装了整个 ReAct 循环：

// createAgent 内部做的事（你无法干预）：
LLM 思考 → 决定调哪个工具 → 执行工具 → LLM 再思考 → ... → 最终回复

这在大多数场景下够用。但当你需要：

  • 在工具执行前审核参数（大额转账需要审批）
  • 记录每次工具调用的审计日志
  • 限制 Agent 的最大步数防止无限循环
  • 在特定条件下暂停等待人工确认

createAgent 就帮不了你了——因为循环逻辑是框架内部的，你插不进去。

LangGraph 给你钥匙。在 LangGraph 中，ReAct 循环不是黑盒——它是三个显式的组件（LLM 节点、工具节点、路由器），你可以在任意两个组件之间插入自定义逻辑。

先跑代码

cd learn-langchain
npx tsx 08-langgraph-agent.ts

三个演示依次运行：手动 ReAct → 注入审核步骤 → 追踪执行统计。

核心架构：三个组件拼出 ReAct

┌─────────────────────────────────────────────┐
│              LangGraph ReAct 循环            │
│                                             │
│   START ──→ ┌──────┐                        │
│             │ LLM   │ ← model.bindTools()    │
│             │ 节点   │   决定: 回复 or 调工具  │
│             └──┬───┘                        │
│                │                            │
│         有 tool_calls?                       │
│         ┌──────┴──────┐                     │
│         │ YES         │ NO                  │
│         ▼             ▼                     │
│    ┌─────────┐      END                    │
│    │ 工具节点  │  执行 tool_calls            │
│    │          │  返回 tool message          │
│    └────┬────┘                             │
│         │                                   │
│         └──→ 回到 LLM 节点（继续推理）        │
└─────────────────────────────────────────────┘

1. LLM 节点 — 模型决策

const llmNode = async (state) => {
  // bindTools 让模型知道它有哪些工具可以调用
  const modelWithTools = model.bindTools(toolDefinitions);
  const response = await modelWithTools.invoke(state.messages);

  // response.tool_calls 可能是:
  //   [] → 模型直接回复了文本
  //   [{name: "calculator", args: {expression: "3+5"}}] → 请求调工具
  return { messages: [response] };
};

2. 工具节点 — 执行工具调用

const toolNode = async (state) => {
  const lastMsg = state.messages.at(-1);
  const toolCalls = lastMsg.tool_calls ?? [];

  const results = await Promise.all(
    toolCalls.map(async (tc) => {
      const fn = toolsByName[tc.name];         // 找到对应函数
      const output = await fn(tc.args);        // 执行
      return { role: "tool", tool_call_id: tc.id, content: output };
    })
  );

  return { messages: results };  // 工具结果追加到消息历史
};

3. 路由器 — 决定下一步

function routeAfterLlm(state) {
  const lastMsg = state.messages.at(-1);
  return lastMsg.tool_calls?.length ? "tools" : END;
  //       有 tool_calls → 去执行工具
  //       没有 → 结束（模型已经给出最终回答）
}

核心价值：插入自定义步骤

因为三个组件都是你自己写的，你可以在任意位置插入步骤：

// createAgent 做不到的事：
LLM → 🛡️ 审核节点（检查工具参数是否安全）
    → 🚫 危险操作直接拒绝，不执行工具
    → ✅ 安全操作通过，继续执行

// 你还可以插入：
LLM → 📊 日志节点（记录推理过程到数据库）
    → ⏱️ 限流节点（防止调用过快）
    → 🔧 工具节点
    → ✅ 验证节点（检查工具返回是否合法）
    → LLM → END
演示 2 的审核步骤就是最好的例子：正常计算 3×5 通过审核→执行工具→LLM 回复。但 99999×99999 被审核拦截，Agent 直接回复「拒绝执行」而不碰工具。

演示 3: 自定义 State 追踪执行过程

因为 LangGraph 的 State 可以包含任意字段，你可以追踪每一轮的执行统计：

const MonitorState = Annotation.Root({
  messages: Annotation({ /* 消息累积 */ }),
  llmCallCount:    Annotation({ reducer: (_, r) => r }),      // LLM 调用次数
  toolCallCount:   Annotation({ reducer: (_, r) => r }),      // 工具调用次数
  toolCallHistory: Annotation({ reducer: (l, r) => [...l, ...r] }), // 工具调用链
});

// 运行后可以拿到：
// { llmCallCount: 2, toolCallCount: 3, toolCallHistory: ["get_user_profile(...)", "calculator(...)", ...] }

LangGraph Agent vs createAgent — 精确对比

能力 createAgent LangGraph Agent
ReAct 循环 ✅ 内置 🔧 手动构建
工具调用 ✅ 自动 🔧 自己写工具节点
插入审核/日志 ❌ 不支持 ✅ 任意位置插入
步数限制 ❌ maxSteps 不可控 ✅ 在路由器中自己数
执行追踪 ❌ 只能看消息 ✅ 自定义 State 字段
代码量 ~10 行 ~60 行
结论：createAgent 适合 80% 的场景（快速原型、简单对话），LangGraph Agent 适合需要精细控制的 20%（审批流、审计、限流、多 Agent 编排）。两者不互斥——你可以在 LangGraph 的子图中使用 createAgent。
